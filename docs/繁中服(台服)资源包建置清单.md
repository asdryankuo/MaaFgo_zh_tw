# 繁中服（台服）资源包建置清单

目标：让 MaaFgo 能识别并操作繁体中文版 FGO（[fate-go.com.tw](https://www.fate-go.com.tw/)）客户端画面，
新增第三个资源层 `tw`，与现有 `cn`（简中）、`base`（日服，同时也是默认素材层）并列。

## 已完成（代码 / 配置骨架）

- `agent/custom/box_action.py`、`formation_action.py`、`servant_up_action.py`、
  `general_navigation_action.py`、`support_action.py`：原本 `pkg = "cn" if resource_package == "cn" else "base"`
  的二选一判断，已改为 `pkg if pkg in ("cn", "tw") else "base"`，让 `resource_package="tw"` 时
  能正确解析到 `resource/tw/...` 目录，缺图时仍会回退到 `base`。
- `assets/resource/tw/image/`、`assets/resource/tw/pipeline/`：新建空目录（含 `.gitkeep`），
  用来放置台服专属覆盖图与 pipeline 覆盖。
- `assets/options/资源包类型.json`：新增 `资源包类型-tw` 选项，`attach.resource_package` 设为 `"tw"`。
- `assets/interface.json`：`resource` 清单新增 `"台服(繁体中文)"` 条目，
  `path: ["resource/base", "resource/tw"]`。
- `assets/options/包名填写.json`：新增 `"台服"` case，`package` 暂时填占位字符串
  `"TODO_FILL_TW_PACKAGE_NAME"`（明显不是合法包名，不会误伤到其他 App），
  等拿到真实 package name 后直接替换这个字符串即可（`打开游戏`/`关闭游戏`/`登录-关闭游戏` 三处都要改）。

在没有任何 `tw` 素材之前，选择「台服(繁体中文)」目前等同于选日服（全部回退到 `base`），
不会报错，可以安全地先合并这部分骨架。

### 3. Pipeline 覆盖（`assets/resource/tw/pipeline/...`）

`resource/cn` 目前只覆盖了 `login.json`、`关闭游戏.json`（额外弹窗 / 流程分支），
`resource/jp` 覆盖了 `run_FGO.json`、`关闭游戏.json`。若台服登入流程有额外的公告、
实名认证、隐私权同意等简中/日服没有的弹窗，需要另外写 `resource/tw/pipeline/` 覆盖节点，
而不能只靠换图解决。这部分要等实际跑过登入流程才能确定。

**已知案例**：`resource/tw/pipeline/每日免费友情.json` —
台服「每日免费友情」已用完时，不会像 base/cn 一样落在能用 `友情池1抽.png` 判断的画面，
而是直接落在纯付费的「友情點數召喚」页面（无免费选项）。base 的完成判断
（OCR "耗尽" / 模板 `友情池1抽.png`）在这个画面上永远不会命中，会一直点「下一个卡池」
最多 99 次才放弃。修法：新增 `每日免费友情-完成3` 节点，用台服这个画面的截图
（`resource/tw/image/每日友情抽取完成.png`）做 TemplateMatch，并把
`每日免费友情-召唤开始` 节点整个重新定义（pipeline 覆盖是整节点替换，不是深度合并）
把新节点加进 next 候选列表。

`每日1抽.json` / `常驻每日1抽.json` 里也有几乎一样的 OCR "耗尽" 完成判断逻辑，
台服这两个任务如果也卡在「选择下一个卡池（最多找99次）」，大概率是同样原因，
需要看玩家截图后比照这个案例加对应的 tw pipeline 覆盖。
